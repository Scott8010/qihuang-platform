## 6. 单树化论证（为什么"外层"是死副本）

经 git 历史、CI 配置、生产机器、引用关系逐项核查，外层根级树与嵌套树**不是镜像、是严重分叉**：

| 维度 | 嵌套树 `qihuang_platform/`（内层） | 外层根级 `capability/ gateway/` 等 |
|---|---|---|
| git 演进 | 从 Initial 持续演进到最新（活） | 所有同名文件停更于 Initial（死） |
| 功能完整度 | 更全（多 education/medical/health_probe/llm_fallback/monitor/redis/billing全套） | 更少（仅 Initial 快照） |
| CI 部署 | `SOURCE="qihuang_platform/"` → 唯一被部署 | **从不部署外层** |
| 生产机器 | 生产真跑这份 | 根级无外层目录（仅 1 个死 main.py，已清） |
| 活代码引用 | `from qihuang_platform.xxx` 全指向它 | **零裸导入、零启动配置引用** |
| 包声明 | — | pyproject/setup **无 packages 声明** → 不在 Python 解析路径 |

**结论**：外层是 Initial 提交遗留快照，从未演进/部署/加载/引用 → 是死档案，不是"活的第二棵树"。正确动作是**删外层遗留**，而非"合并"。

## 12. 后续修复（2026-09-13 追加）

### 12.1 问题：「system 知识审核驳回」待办卡片跳到了监控运维

**根因**：
- 后端 `/admin/v1/dashboard` 只返回 `review`（计数对象），不返回待审列表；前端 `api.ts` 里 `fetchDashboard` 把 `reviews` **硬编码成 `[]`**
- 于是首页「知识审核」待办永远为空；审核驳回事件只能混进审计日志 `recent_ops`，被 `Dashboard.tsx` 当成「系统告警」展示，并按系统告警规则跳转到「监控运维」

**修复**（commit `36d9226`）：
- `Dashboard.tsx` 新增并行调用 `/admin/v1/kg/review/pending`（`fetchReviews`），首页正确展示真实待审知识列表
- `api.ts` 的 `fetchDashboard` 不再丢弃后端可能返回的 `reviews` 列表，透传并兼容映射
- `Dashboard.tsx` 对审计日志里含「审核/驳回/待审/review」字样的兜底事件，自动归类为「知识审核」并跳「内容管控」，不再错跳监控运维
- 重新构建 React（新 bundle hash `index-DIzvUfFy.js`），强制客户端刷新缓存

**生产验证**：新 bundle 含 `kg/review/pending`（1 次）、`content` 跳转修复（1 次）、`/admin/billing_ledger.html`（1 次）、「双账本」（1 次）。

### 12.2 问题：双账本菜单没看到

**根因**：浏览器缓存了旧的 JS bundle。生产代码里一直有 `id:"ledger",label:"双账本"`。

**处理**：本次构建生成新的 JS bundle hash，浏览器加载新 `index.html` 时会强制刷新 JS 缓存。若仍看不到，请按 `Ctrl+F5` 硬刷新或清除浏览器缓存。
