岐黄智脑商业化平台（8602）· 服务器部署标准作业流程

Standard Operating Procedure · 任何改动发版都必须按此流程走，禁止"凭记忆部署"
文档版本：v1.0 生效日期：2026-08-10 适用范围：qihuang_platform 全部改动（CI/CD → 服务器 8602） 配套铁律：RULES.md #18 [岐黄专属]

一、核心原则（三条不能破）

① push ≠ 成功GitHub Actions 的 lint + test(3.13) + test(3.12) + deploy 四个 job 全 success，且服务器实测通过，才算成功。
② 本地验证必须 fresh清 pytest 缓存、用全新数据库，不能用陈旧 test DB 推断"测试过了"。
③ 接口 JSON ≠ 页面部署后必须实测页面 HTTP 200，不能把 /platform/health 的 JSON 当成"页面已上线"。

三、红线（禁止项 · 违反即视为部署事故）

  • 红线1：禁止把接口健康检查 JSON（如 /platform/health 返回的 {"status":"ok"}）当成"页面已部署"。页面入口是 /admin/、/admin-static/*.html。
  • 红线2：禁止 push 后未确认 CI 实际状态（四 job 全绿）就声称"部署成功"。这是 2026-08-09 误报老黄的根因。
  • 红线3：禁止仓库根目录存在与包内同名的模块目录（./control、./rbac 等）。pytest 加载错模块 → test 红 → CD 门禁挡住 → 部署不跑。
  • 红线4：禁止提交未 git add 的前端文件。untracked 文件 CD（rsync git checkout）不会同步，服务器上页面 404。
  • 红线5：禁止用陈旧 test DB 推断测试通过。旧数据残留会制造假失败（如重复用户返回 400 误判）。每次用全新 DB 文件。

五、故障与回滚

情况 A：CI 红（test/lint failure）
→ 本地修复 → 重新 git push，CI 自动重跑。不要绕过门禁强制部署。

情况 B：部署后页面/接口异常
→ 服务器紧急回滚到上次好版本：

# SSH 进服务器
ssh root@111.231.63.73
cd /root/qihuang_platform
git log --oneline -5          # 找到上次好的 commit
git checkout <上次好commit>  # 回滚代码
systemctl restart qihuang-platform   # 或对应重启 8602 的指令
curl http://localhost:8602/platform/health   # 确认 ok

情况 C：404 疑似部署未完成
→ 先等 1-2 分钟同步窗口再探测；仍 404 才判定文件未同步，检查 git 是否 tracked + CD 是否跑过。
