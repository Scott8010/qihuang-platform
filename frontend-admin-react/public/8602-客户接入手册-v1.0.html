1. 平台介绍

岐黄智脑 8602 是一站式大健康 AI 中台，向客户暴露 8 项可调用的 Agent 能力 + 1 项合规内容审核能力 + 1 项玄学起卦能力。所有能力通过统一的 HTTP API 调用，鉴权使用 JWT Bearer Token。

健康咨询1中医健康顾问（health-advisor）
教育培训2中医辨证教练（coach）、门店话术教练（store-coach）
内容生产1文案生成（content-writer）
经营诊断1数据洞察（insight）
合规审核1内容合规（compliance）
玄学起卦1六爻起卦（fortune）
地理视觉1地理健康视觉（geo）

基础信息

  • API 网关：http://111.231.63.73:8602（生产）
  • 路径前缀：/api/v1/agent/<key>/<action>
  • 内容类型：application/json; charset=utf-8
  • 字符编码：UTF-8
  • 时区：UTC（所有时间戳为 UTC ISO8601 字符串）

2. 凭据说明

客户开通后，运营方在 8602 控制台「租户详情 → API 密钥」为该客户签发一对凭据：

字段含义格式示例
app_key应用 Key（公开标识符，登录时当 username 用）ak_<32位hex>ak_7e5722682d954b39...
app_secret应用 Secret（私密登录密码，仅显示一次）sk_<64位hex>sk_a1b2c3...（64 hex）
🔴 SK 永不再显示 · 签发那一瞬间控制台显示一次，关闭页面后永远不可再查。客户必须当场复制保存到本地 .env（加入 .gitignore）。如丢失只能走运营方轮换密钥（轮换期间旧密钥 72 小时内仍可用，避免突然断流）。

推荐本地存储

请把以下内容存入项目根目录的 .env（gitignored）：

.env
# === 岐黄智脑 8602 接入凭据 ===
# 妥善保管，不要提交到 git / 不要发到聊天框
QH_BASE_URL=http://111.231.63.73:8602
QH_TENANT_ID=<你的租户 ID，由运营方提供>
QH_APP_KEY=ak_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
QH_APP_SECRET=sk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

登录拿 JWT 后，把 access_token 也写入 .env 或运行时缓存（2 小时过期，需用 refresh_token 续期）。

3. JWT 鉴权流程

8602 当前为内部租户提供 JWT Bearer Token 鉴权路径（/api/v1/auth/login），客户后端先登录拿 token，再用 token 调 Agent API。

3.1 登录拿 Token

POST /api/v1/auth/login
curl -X POST $QH_BASE_URL/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "login_type": "password",
    "username": "'"$QH_APP_KEY"'",
    "password": "'"$QH_APP_SECRET"'"
  }'

响应：

{
  "code": 0,
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "refresh_token": "eyJhbGciOiJIUzI1NiIs...",
    "token_type": "bearer",
    "expires_in": 7200
  }
}
字段含义
access_token访问 Token，2 小时有效，调 Agent API 时放 Authorization 头
refresh_token刷新 Token，30 天有效，access_token 过期时用来换新 access_token
expires_inaccess_token 有效期（秒），默认 7200（2 小时）

3.2 调 Agent API（带 Token）

Authorization: Bearer <access_token>
curl -X POST $QH_BASE_URL/api/v1/agent/health-advisor/consult \
  -H "Authorization: Bearer $QH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "question": "最近失眠、乏力",
    "profile": {"age": 35, "gender": "female"}
  }'

3.3 Token 过期 → 自动刷新

POST /api/v1/auth/refresh
curl -X POST $QH_BASE_URL/api/v1/auth/refresh \
  -H "Content-Type: application/json" \
  -d '{ "refresh_token": "'"$QH_REFRESH_TOKEN"'" }'

响应同 3.1。建议客户实现一个 Token 管理器：检测到 401 TOKEN_EXPIRED 自动 refresh 后重试。

5. 错误码对照表

所有 8602 接口返回统一信封：{ code, message, data }。code=0 表示成功，其它 code 为业务错误。

code标识含义建议处理
0SUCCESS成功正常处理 data
1001UNAUTHORIZED缺少认证 Token检查 Authorization 头是否带 Bearer
1002TOKEN_EXPIREDaccess_token 过期用 refresh_token 换新 token 后重试
1003TOKEN_INVALIDtoken 无效 / 被吊销重新走 /auth/login 流程
2001QUOTA_EXCEEDED本月套餐配额用尽联系运营方升级套餐 或 等下月恢复
2002API_KEY_INVALIDAK/SK 错误或被吊销检查 .env 配置；如确认无误联系运营
2008AGENT_FORBIDDEN该能力未在套餐/授权内联系运营方叠加 addon 授权
4001VALIDATION_FAILED请求参数不合法检查必填字段 / 字段类型
429RATE_LIMITED触发限流退避重试（建议指数退避）
5000INTERNAL_ERROR服务端异常带 request_id 联系运维

7. 安全规范

🔴 三条不可逾越的红线
  1. SK 绝不进 git / 不进聊天框 / 不存进明文文档。客户应把 SK 写到本地 .env（gitignored）。
  2. SK 误传 = 立即吊销。如已误传到任何外部通道，立刻通知运营方吊销重发。
  3. access_token 不要给前端。JWT 仅在客户后端内部流转，前端通过客户后端的 BFF 层转发调用，避免 token 进入浏览器。

推荐做法

  • 客户后端用 内存缓存 + 过期前 5 分钟自动 refresh 持有 access_token
  • 客户后端实现请求重试：收到 1002 TOKEN_EXPIRED 自动 refresh 后重试原请求
  • 客户后端实现指数退避：收到 429 RATE_LIMITED 按 1s / 2s / 4s / 8s 退避
  • 所有 API 调用走服务端发起，token 不进浏览器 / 不进小程序 storage

8. 常见问题

Q1. SK 丢失了怎么办？

SK 控制台不可查。联系运营方走「轮换密钥」流程：运营方在控制台调轮换，旧 SK 在 72 小时内仍可用，新 SK 一次性展示给客户。

Q2. 套餐升级什么时候生效？

升级是次月 1 号生效，当月仍按原套餐计费与鉴权。运营方控制台会显示「待生效预约」徽章。

Q3. 套餐配额用完了还能用吗？

不能。配额用尽后调用返 2001 QUOTA_EXCEEDED，需升级套餐或等下月 1 号恢复。

Q4. /open/v1/* 是什么？怎么用？

/open/v1/* 是面向外部第三方（不登录）的 HMAC 签名 API 路径，目前仅供演示，未正式启用。如需启用请联系 8602 商务。

Q5. 支持哪些客户端语言？

任何能发 HTTP 的语言都行。文档示例用 curl，客户可用 Python requests / Node axios / Java OkHttp / Go net/http 等。

客户端示例（Python）

qh_client.py
import os
import time
import requests
from dotenv import load_dotenv

load_dotenv()

BASE = os.environ["QH_BASE_URL"]
APP_KEY = os.environ["QH_APP_KEY"]
APP_SECRET = os.environ["QH_APP_SECRET"]

class QHClient:
    def __init__(self):
        self.token = None
        self.token_exp = 0

    def _login(self):
        r = requests.post(f"{BASE}/api/v1/auth/login", json={
            "login_type": "password",
            "username": APP_KEY,
            "password": APP_SECRET,
        }, timeout=10).json()
        if r.get("code") != 0:
            raise RuntimeError(f"login failed: {r}")
        d = r["data"]
        self.token = d["access_token"]
        self.refresh_token = d["refresh_token"]
        self.token_exp = time.time() + d["expires_in"]

    def _refresh(self):
        r = requests.post(f"{BASE}/api/v1/auth/refresh", json={
            "refresh_token": self.refresh_token,
        }, timeout=10).json()
        d = r["data"]
        self.token = d["access_token"]
        self.refresh_token = d["refresh_token"]
        self.token_exp = time.time() + d["expires_in"]

    def call(self, method, path, **kwargs):
        if not self.token or time.time() >= self.token_exp - 60:
            self._login()
        headers = kwargs.pop("headers", {})
        headers["Authorization"] = f"Bearer {self.token}"
        r = requests.request(method, f"{BASE}{path}", headers=headers, timeout=30, **kwargs)
        if r.status_code == 401 and r.json().get("data", {}).get("code") == 1002:
            self._refresh()
            headers["Authorization"] = f"Bearer {self.token}"
            r = requests.request(method, f"{BASE}{path}", headers=headers, timeout=30, **kwargs)
        return r.json()

# 使用示例
qh = QHClient()
resp = qh.call("POST", "/api/v1/agent/health-advisor/consult", json={
    "question": "最近失眠、乏力",
    "profile": {"age": 35, "gender": "female"},
})
print(resp["data"]["reply"])

附录 B · HMAC 签名（/open/v1/* 外部 API 场景）

/open/v1/* 路径采用 HMAC-SHA256 签名鉴权，面向不登录的外部第三方 API 调用场景。当前仅供演示，未来如需正式启用，本节将补充完整文档。

签名串格式：

{app_key}\n{method}\n{path}\n{timestamp}\n{nonce}\n{body}
  • 算法：HMAC-SHA256，hex 编码
  • 时间窗：±5 分钟（请求 timestamp 与服务端时间差不能超过 300s）
  • 请求头：X-App-Key / X-Signature / X-Timestamp / X-Nonce
  • 密钥轮换：旧密钥 72 小时内并行有效

客户当前不需要关心本节，使用第 3 章 JWT 路径即可。
