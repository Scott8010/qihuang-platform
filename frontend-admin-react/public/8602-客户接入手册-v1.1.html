2. 凭据说明

客户开通后，运营方在 8602 控制台「租户详情 → API 密钥」为该客户签发一对凭据：

字段含义格式示例
app_key应用 Key（公开标识符，登录时当 username 用）ak_<32位hex>ak_7e5722682d954b39...
app_secret应用 Secret（私密登录密码，仅显示一次）sk_<64位hex>sk_a1b2c3...（64 hex）
🔴 SK 永不再显示 · 签发那一瞬间控制台显示一次，关闭页面后永远不可再查。客户必须当场复制保存到本地 .env（加入 .gitignore）。如丢失只能走运营方轮换密钥（轮换期间旧密钥 72 小时内仍可用，避免突然断流）。

3.1 Agent API 鉴权：HMAC-SHA256 签名（舌诊/健康顾问等 /api/v1/agent/*）

每个请求带 4 个签名头，服务端用 app_secret 校验签名、防重放（5 分钟 + nonce 去重）：

请求头
X-App-Key: <app_key>
X-Timestamp: <当前 Unix 秒时间戳>
X-Nonce: <随机字符串，每次请求唯一>
X-Signature: <HMAC-SHA256 签名十六进制串>

签名串拼接规则（换行符 \n 分隔，body 为原始请求体字符串，GET 为空）：

message = f"{app_key}\n{method}\n{path}\n{timestamp}\n{nonce}\n{body}"
signature = HMAC-SHA256(key=app_secret, msg=message).hexdigest()

其中 method 为大写（POST/GET）、path 为请求路径（如 /api/v1/agent/tongue/analyze）。body 必须与发送的请求体完全一致（字节级），否则签名不匹配。

Python 示例 · 舌诊分析
import os, time, uuid, hmac, hashlib, json, requests
APP_KEY=os.environ["QH_APP_KEY"]; SECRET=os.environ["QH_APP_SECRET"]
BASE=os.environ["QH_BASE_URL"]
path="/api/v1/agent/tongue/analyze"
body=json.dumps({"image":"data:image/png;base64,..."},separators=(",",":"))
ts=str(int(time.time())); nonce=uuid.uuid4().hex
msg=f"{APP_KEY}\nPOST\n{path}\n{ts}\n{nonce}\n{body}"
sig=hmac.new(SECRET.encode(),msg.encode(),hashlib.sha256).hexdigest()
r=requests.post(BASE+path,data=body,headers={
  "Content-Type":"application/json","X-App-Key":APP_KEY,
  "X-Timestamp":ts,"X-Nonce":nonce,"X-Signature":sig},timeout=30)
print(r.json())
✅ 舌诊返回语义（v1.1 更新） · 成功时 code=0, data.mode="vision"（含 tongue 结构化标签）；上游视觉模型故障时 code=5003、data.mode="image_error"、data.degraded=true——请按 code≠0 或 degraded=true 判定平台侧故障走兜底，不要把 mode=image_error 当成功。

3.2 对话鉴权：Bearer app_key（/v1/chat/completions，OpenAI 兼容）

对话端点走 OpenAI 兼容协议，鉴权头直接放 app_key（不是 JWT、不需要签名）：

POST /v1/chat/completions
curl -X POST $QH_BASE_URL/v1/chat/completions \
  -H "Authorization: Bearer $QH_APP_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "health-assistant",
    "messages": [{"role":"user","content":"最近失眠、乏力"}]
  }'

先调 GET /v1/models（同样 Bearer app_key）可列出可用模型。

5. 错误码对照表

所有 8602 接口返回统一信封：{ code, message, data, trace_id }。code=0 表示成功，其它 code 为业务错误（含 trace_id 便于定位）。

code标识含义建议处理
0SUCCESS成功正常处理 data
1001-1003INVALID_PARAM参数错误 / 缺参 / 格式错检查入参字段
2001UNAUTHORIZED未授权（签名头缺失或无效）检查 HMAC 签名头 / Bearer app_key
2003TOKEN_INVALID凭据无效 / 被吊销检查 AK/SK 配置；如吊销联系运营重签
2006SIGNATURE_MISMATCHHMAC 签名不匹配核对签名串拼接（含 body 字节一致）与时间
2007TIMESTAMP_EXPIRED签名时间戳过期（>5 分钟）用当前时间重新签名，勿用旧 timestamp
2008AGENT_FORBIDDEN该能力未在套餐/授权内联系运营方叠加 addon 授权（注册≠授权）
3001RATE_LIMITED触发限流退避重试（建议指数退避）
3002QUOTA_EXCEEDED本月积分/配额用尽充值积分或升级套餐
5003LLM_DOWN上游视觉/AI 模型故障（如舌诊 mode=image_error）按 data.degraded=true 走业务兜底，稍后重试；带 trace_id 报障
6001NOT_FOUND资源不存在检查路径 / ID
6004COMPLIANCE_BLOCKED内容合规拦截调整内容后重试

7. 安全规范

🔴 三条不可逾越的红线
  1. SK 绝不进 git / 不进聊天框 / 不存进明文文档。客户应把 SK 写到本地 .env（gitignored）。
  2. SK 误传 = 立即吊销。如已误传到任何外部通道，立刻通知运营方吊销重发。
  3. app_secret 不要给前端。签名在客户后端内部完成，前端通过客户后端的 BFF 层转发调用，避免 secret 进入浏览器 / 小程序 storage。

推荐做法

  • 每次请求现算 HMAC 签名（timestamp 取当前秒、nonce 每次唯一），不要缓存签名复用
  • 客户后端实现请求重试：收到 2007 TIMESTAMP_EXPIRED 重新签名后重试原请求
  • 客户后端实现指数退避：收到 429 RATE_LIMITED 按 1s / 2s / 4s / 8s 退避
  • 所有 API 调用走服务端发起，app_secret 不进浏览器 / 不进小程序 storage

8. 常见问题

Q1. SK 丢失了怎么办？

SK 控制台不可查。联系运营方走「轮换密钥」流程：运营方在控制台调轮换，旧 SK 在 72 小时内仍可用，新 SK 一次性展示给客户。

Q2. 套餐升级什么时候生效？

升级是次月 1 号生效，当月仍按原套餐计费与鉴权。运营方控制台会显示「待生效预约」徽章。

Q3. 套餐配额用完了还能用吗？

不能。配额用尽后调用返 2001 QUOTA_EXCEEDED，需升级套餐或等下月 1 号恢复。

Q4. /open/v1/* 是什么？怎么用？

/open/v1/* 是面向外部第三方（不登录）的 HMAC 签名 API 路径，已正式启用（与 /api/v1/agent/* 同为 HMAC 鉴权）。签名用法见第 3.1 节。

Q5. 支持哪些客户端语言？

任何能发 HTTP 的语言都行。文档示例用 curl，客户可用 Python requests / Node axios / Java OkHttp / Go net/http 等。

    ts=str(int(time.time())); nonce=uuid.uuid4().hex
    msg=f"{APP_KEY}\n{method}\n{path}\n{ts}\n{nonce}\n{body_str}"
    sig=hmac.new(SECRET.encode(),msg.encode(),hashlib.sha256).hexdigest()
    return {"Content-Type":"application/json","X-App-Key":APP_KEY,
            "X-Timestamp":ts,"X-Nonce":nonce,"X-Signature":sig}

def agent_call(path, payload):
    body=json.dumps(payload,separators=(",",":"))
    r=requests.post(BASE+path,data=body,headers=signed_headers("POST",path,body),timeout=30)
    return r.json()

def chat(messages):
    # 对话端点：Bearer app_key（OpenAI 兼容）

        json={"model":"health-assistant","messages":messages},timeout=30)

附录 B · HMAC 签名（/open/v1/* 外部 API 场景）

HMAC-SHA256 签名是 /api/v1/agent/* 与 /open/v1/* 的正式鉴权方式（v1.1 起为主要接入路径）。签名串、时间窗、请求头详见第 3.1 节，本节汇总实现要点。

签名串格式：

{app_key}\n{method}\n{path}\n{timestamp}\n{nonce}\n{body}
  • 算法：HMAC-SHA256，hex 编码
  • 时间窗：±5 分钟（请求 timestamp 与服务端时间差不能超过 300s）
  • 请求头：X-App-Key / X-Signature / X-Timestamp / X-Nonce
  • 密钥轮换：旧密钥 72 小时内并行有效

本节为 HMAC 签名的实现细节补充，客户按第 3 章接入即可；遇到签名不匹配时回查本节。
